Companion to "A Sketch of Everything" · Human Factors Brief

One pothole app, seven prompts

Each prototype below was generated by a general-purpose AI model in a fresh session that had seen none of the others, on October 5, 2026. The prompts are shown exactly as sent. The prototypes are unedited. The only shared instruction beyond the design request was a technical one: wrap each screen in a tagged section so screens could be counted.

The point of the demonstration is narrow. A style instruction changes how a prototype looks. It does not reduce what the prototype contains, and depending on how it is worded, it can quietly remove what a test needs.

C · Scope stated before style

Build a clickable prototype of a mobile web app that lets residents report potholes to their city.

Scope: one task only. A resident reports a single pothole: marks its location, optionally adds a photo, and receives a confirmation. Three screens maximum. Out of scope: accounts or sign-in, report history, status tracking, notifications, settings, onboarding, and any other feature.

Render it as a hand-drawn grayscale wireframe with placeholder text, no color or imagery.

Three screens: location, photo and submit, confirmation. The task copy survived ("Tap the map where the pothole is"), with placeholders only around it.

D1–D3 · Three alternatives for the price of one

The same scoped prompt as C, each with one added line naming a different starting point. Showing participants three alternatives rather than one is the move the research supports for getting candid criticism; at this cost there is little reason not to.

Design approach: map-first. The resident starts by placing the pothole on a map.
Design approach: camera-first. The resident starts by taking a photo, and location comes from the photo or the device.
Design approach: address-first. The resident starts by typing or confirming a street address or nearest intersection.

Limits

This is one flow, one model, one run per prompt. Another run of the same prompt could produce a different screen count or keep more or less copy. The demonstration shows that scope and style are separate controls and that a style instruction can change content as well as appearance. It does not show what participants would say about any of these versions.
